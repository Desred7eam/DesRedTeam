## 第 0 章 · 项目简介

DesRedTeam 整合**信息收集 · 资产测绘 · 漏洞验证 · WebShell 管理 · C2 控制 · 项目记忆 · AI 审批围栏**，
构建完整的攻防作业流水线。从信息收集到打点突破，由 Hermes 与 DSH 原生驱动。

**核心能力域：**

| 能力域        | 说明                                            |
| ------------- | ----------------------------------------------- |
| 信息收集      | 域名 / 子域 / ICP / 邮箱 / 股权穿透 / 供应链    |
| 资产测绘      | FOFA / Quake / ZoomEye / Shodan 通道 + 指纹识别 |
| 漏洞验证      | 框架指纹 → 打法匹配 → 只读验证（非破坏性）      |
| 主机与容器    | 配置核查、弱口令合规测试、容器配置审查          |
| WebShell 管理 | 哥斯拉系 MCP 前端适配                           |
| C2 控制       | DesShell（仅限靶机 / 授权环境）                 |
| 落库与报告    | pentrack MCP 资产入库 + 漏洞推送 + 证据链保全   |

> **本项目不含、不提供、不分发任何"开箱即用"的恶意载荷、免杀武器、勒索/销毁型功能。**
> A 线 / B 线自动化攻击脚本因法律风险**永久不予开源分发**（见 §2.4）。

## 第 1 章 · v3.0 能力更新

### 1.1 DSH 原生 Harness

DSH 原生 Harness 作为底层执行调度能力，内置高命中率缓存体系，对重复请求、重复计算片段做复用加速，
大幅削减二次执行的资源消耗，规避反复初始化带来的性能损耗。

配套特调的极简运行模式，自动裁剪冗余模块、关闭非必要扩展特性，不加载额外插件与可选逻辑。
专门面向标准化、可复用的固定工作流场景深度优化，信息收集效率大幅度提升。
聚焦既定流程的落地执行，让每一轮任务都能稳定发挥，输出效果可复现、执行时延波动小。

Hermes 回归原生官方 Web UI，并入 DRT 体系，通过 pentrack MCP 实现资产项目入库与漏洞推送。

### 1.2 DRT 模式 —— 全局缓存管理

DRT 模式是对 DSH 二次开发得到的自定义运行模式，深度并入 DesRedTeam 平台。
裁剪规划交互、多代理调度等冗余逻辑，内置 65 套渗透 playbook，单线连续执行，保全完整证据链，
适配资产信息收集，借助全局缓存实现高速稳定自动化作业。

### 1.3 Harness 极简模式 —— 执行强确定性

依托改造完成的内核，启用 DSH 原生 Harness 调度底座的极简运行模式特调版本。
主动裁剪各类冗余扩展模块，关闭动态多场景兼容逻辑、可选插件加载、动态环境适配等非核心能力。

剔除外来组件动态加载、配置动态变更带来的变量干扰，只保留固定工作流所必需的最小执行链路。
主动舍弃面向多样化临时任务的泛化兼容能力，以此换取执行过程的强确定性。
整个运行环境状态高度收敛，减少运行时随机扰动，避免因为组件动态变化引发的偶发异常。

### 1.4 场景价值 —— 固定工作流稳定输出

在内核归位、高命中缓存、极简调度模式三者协同驱动之下，整套架构针对定型的**企业信息收集**工作流
完成专项能力释放。

全局高命中缓存可大量复用历史探测结果、域名资产、接口指纹、解析记录等中间数据，
避免每一轮任务重复发起网络请求、重复解析运算，有效抑制多次任务之间的性能漂移，
多轮信息收集执行结果高度可复现。面对企业资产摸排这类标准作业，可实现 **2 分钟完成某公司完整信息收集**
（数据均来自互联网公开渠道，**严禁未授权渗透测试**）。

### 1.5 收集落库路径 —— 一条龙自动

`COLLECT · STORE · WEAVE`

供应链 = 招投标信息、互联网搜索、系统暴露、其他媒介发现的灰度资产，每一张卡片都带完整证据链。
信息收集完成后，攻击路径视图自动编织，不再空白。

> 相关数据来自互联网，经小蓝本等公开渠道获取。**严禁未授权测试！**

### 1.6 最新漏洞成果

## 第 3 章 · 授权前提与 Scope 冻结

### 3.1 授权文件最低要件

一份可用的授权书至少应包含：

1. 授权方与被授权方**全称**及签署人职务；
2. **目标资产清单**（域名 / IP 段 / 应用名 / 云账号，逐条列明）；
3. **授权时间窗口**（起止日期与每日可作业时段）；
4. **允许的手法与禁止的手法**（是否允许口令测试、是否允许写入、是否允许重启）；
5. **允许的影响级别**（只读 / 可短时中断 / 可写入数据）；
6. **应急联系人**与**中止口令**（Kill Switch）；
7. 数据保密与销毁条款、成果归属条款。

### 3.2 Scope 冻结纪律

- 资产清单一旦冻结，**新增目标须走变更单**，不得"顺手打一下"；
- **第三方托管资产**（公有云 PaaS 层、CDN 边缘节点、SaaS 平台）不因"我的域名指向它"而进入 Scope；
- 子域 / 新 IP / 新端口若为**同一权利人**所有，可直接纳入并记录；**权属不明**者先确认权属再动作；
- 出网 IP 与作业机标识应提前报备，避免触发目标 SOC 误判。

### 3.3 作业中红线

- **一律禁止**：删库、格式化、不可逆加密、销毁数据、物理破坏；
- **可恢复影响**（重启、短时中断、写数据、改配置）须在 ROE 允许范围内，并**逐次记录**；
- 口令测试**限时限次**（建议 ≤5 分钟 / 目标），触发 429 / 账号锁定特征**立即停止**；
- 发现**第三方已入侵痕迹**（遗留 webshell、异常账号）时**停止利用、保全证据、立即上报**。
